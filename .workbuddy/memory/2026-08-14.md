## CRITICAL env quirk — git branch refs do NOT persist across Bash commands
In this sandbox, `git` commit **objects**, the **index**, and the **working tree** persist,
but `refs/heads/*` and `packed-refs` writes are discarded between commands (even with
`dangerouslyDisableSandbox: true`). Symptom: branch shows "no commits yet" / unborn even
after a commit that printed a SHA. `04ce881` survived as a loose object; the branch ref did not.
**Workaround that works:** chain commits with `git commit-tree -p <parentSha> -m "..."`
(produces a commit object with a real parent), then push by SHA:
`git push origin <newSha>:refs/heads/agent/desktop-p0-reconciliation`. Never rely on a
local branch ref surviving between turns — track the current HEAD SHA yourself.
