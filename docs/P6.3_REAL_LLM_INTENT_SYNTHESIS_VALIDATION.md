## Protocol failure 与 intent fidelity failure

两类失败被明确分开：

| 类别 | 包含 | 证据处理 |
| --- | --- | --- |
| `PROTOCOL_FAILURE` | invalid JSON、schema malformed、truncation、provider 401/429/timeout/transport failure | 记录 provider/error；不得转成语义成功 |
| `INTENT_FIDELITY_FAILURE` | invented constraint/resource/cadence/time/tool/willingness、unnecessary narrowing、证据充分却不收敛 | 只有人工 review 才能确认；JSON 可解析不等于 Intent PASS |

runner 现在分别写入 `protocol_failure`、`intent_fidelity_failure`、
`execution_correctness`、`human_review`、`correction_count`、
`invented_decisions_count` 和 `convergence_turns`。每个 provider generation 都保留
`request_index`、phase、system prompt class、raw response、transport error、
`recovery_used`，并在 phase 下保留 `first_raw_response` / `recovery_raw_response`。
每个 case 的 protocol outcome 明确为 `FIRST_PASS_SUCCESS`、`RECOVERED_SUCCESS` 或
`PROTOCOL_FAILURE`；`intent_fidelity_result` 默认为 `HUMAN_REVIEW_REQUIRED`，不再
用一个 `usable` 指标混合来源。

## Bounded structured-output recovery

provider 已经返回内容但 JSON/schema 不可消费时，当前 seam 最多发起一次格式
恢复请求。恢复使用同一 transcript，不重新询问用户、不扩大意图、不改变 schema；
仍失败则保留原有诚实 fallback/error。HTTP 401、429、timeout 在 provider 调用层
直接保留 transport error，不会进入语义 recovery；合法 JSON 也不会 recovery。

回归覆盖：

- malformed JSON → one recovery → valid；
- malformed JSON → recovery still malformed → fallback；
- 401/429 → one transport call, no semantic recovery；
- valid JSON → no recovery；
- agreement 同样最多一次并保留四字段 contract。
