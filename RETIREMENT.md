# Retirement / Absorption

> Effective: 2026-09-25
>
> Ming Workbench is retained as historical product/engineering research and is no longer an active standalone execution platform.

## Evidence for the decision

Issue #31 `External Reuse & Kill Test` independently accepted:

- Creation Runtime → KILL;
- generic Agent / shell / Python execution → REPLACE;
- generic capability resolver / execution platform → KILL / REPLACE;
- Capability Pack runtime/platform ambitions → retire;
- AAOP active feature development → stop;
- human final acceptance remains human-owned;
- unresolved browser/handoff/no-op questions do not receive infrastructure budget without future real failure.

## What survives

The durable ideas are product/working principles, not this runtime:

1. A person should say what they want to become true, not manage technical ecosystem jargon.
2. The system should borrow the best current capability instead of rebuilding it.
3. Consequential authority remains with the human.
4. Agent/tool/session completion is not proof that reality changed.
5. Real-world readback and human acceptance are the final truth where relevant.

## Destinations

### World-Space

`YuemingHub/World-Space` already owns the ordinary-person product direction:

> find/select/use the best capabilities that already exist, and help a person actually start.

Do not expand World-Space runtime merely to preserve Workbench code. If real World-Space use later reaches delegated execution, the authorization/readback/acceptance principles can be applied there.

### Agent Space

`YuemingHub/agent-workspace` may retain only YueMing-proven cross-task:

- Skills;
- Workflows;
- Recipes;
- Practices;
- adopted external capability pointers.

Do not move Workbench runtime/platform code into Agent Space.

### External ecosystem

Generic execution/workspace/spec/tooling remains replaceable machinery and should be borrowed from mature systems.

## What does not migrate

Do not migrate:

- Creation Runtime;
- generic capability resolver/registry;
- generic execution loop;
- desktop/runtime platform;
- AAOP/Harness integration machinery;
- provider/platform plumbing.

Git history preserves those experiments.

## Open historical work

Old execution-roadmap Issues/PRs are research/history, not the active product queue. They should be closed or left explicitly historical before repository archive.

No new feature work is authorized here.
